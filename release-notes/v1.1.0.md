Everything here came out of pointing Bunyi at a self-hosted model server for
the first time — a set of features that were missing and a set of bugs that
only a slow, multi-gigabyte download could expose.

## New

**See everything you've generated.** A History tab lists every clip, newest
first, with what it said and which voice made it. Play it back with the
progress drawn around the button, save a copy anywhere, copy the details, or
move it to the Trash.

**Every file remembers how it was made.** The text, voice, language, and model
are written inside the WAV itself, so a clip you find months later still says
what produced it. Ordinary audio tools read it too — the title and artist
fields show the text and the voice.

**Manage models without leaving the app.** Settings → Storage lists each
downloaded model with its size, and deletes it to the Trash. Reclaiming ten
gigabytes no longer means hunting through Library folders.

**Save model configurations.** Settings → Models can store the three sources
under a name and switch between them — your own server and the defaults, say —
or reset them all in one click.

**Download the models from Bunyi's own mirror.** Settings → Models now ships a
"Bunyi mirror" configuration: press Restore and the three sources point at
models.bunyi.app instead of Hugging Face. Useful when the Hub is slow, and the
difference between working and not working where the Hub is blocked — which
includes mainland China, not a small detail for a model that speaks Chinese.

It is the same Apache-2.0 models, and Bunyi checks every file against a
published checksum as it downloads. Hugging Face stays the default: it is
where the models actually come from, and Bunyi should not quietly route
everyone through one bucket. Nothing switches on its own — you choose it, and
the file you generate records which one made it.

**Stop what you started.** Generate becomes Stop while anything is running,
and Escape works too. It tells you when it is still winding down rather than
pretending it stopped instantly.

**A help button and a log button**, side by side in the main window. The log
is what explains a download that is taking forever or a run that failed, and
it used to be reachable only from the Window menu. Both stay available while
Bunyi is working, which is exactly when they are wanted. And Bunyi now tells
you how to say its own name.

## Fixed

**Downloads looked stalled when they were fine.** The progress bar advanced
only when a whole file finished — and one file is most of a model — while a
stall warning fired every thirty seconds on a transfer running at full speed.
Progress and stall detection both follow the bytes actually arriving now.

**Stopping a download meant starting over.** Files already fetched are kept;
only what is missing downloads again.

**A half-downloaded model could look complete**, then fail to load with no
explanation. An interrupted download is now recognised as interrupted.

**The script stayed editable while generating**, in every mode, even though
the audio was already being made from what you typed before.

**Preset voice forgot your speaker.** Generating once switched the list to the
model's own names and left the selection blank; your choice is kept.

**Generate is unavailable until a mode has what it needs** — a description for
voice design, a reference clip for voice cloning — and says why on hover.
Previously voice cloning accepted a missing clip and told you only after
downloading several gigabytes.

**Playback broke up a second after a generation finished.** The clip started
playing while the window was still unlocking the controls behind it, and the
audio stuttered once as it did. The same file played from History was always
clean. Playback now lets the window settle before it starts.

**The playback bar rewound instead of resetting.** When a clip finished, the
bar slid back to zero over a quarter second, as though it were scrubbing
backwards. It snaps to zero now.

**Closing the window mid-run** now stops the work first and closes once it has
actually stopped.

## For anyone self-hosting models

There is now a full guide in
[SELF-HOSTING.md](https://github.com/shaztechio/bunyi-app/blob/v1.1.0/SELF-HOSTING.md):
what the app requires, a walkthrough from a standing start with Cloudflare R2,
which hosts cannot work and why, and what to check when it goes wrong. Once
your bucket is serving,
[CACHING.md](https://github.com/shaztechio/bunyi-app/blob/v1.1.0/CACHING.md)
covers putting it behind a CDN.

**Your server can publish checksums, and Bunyi will check them.** Add a
`manifest.sha256` next to your `manifest.txt` — it is exactly what
`shasum -a 256` prints — and every file is verified as it arrives. A truncated
upload or a half-finished sync used to produce a model that loaded and spoke
nonsense, with nothing to say why; now it stops and tells you which file is
wrong. Servers without one keep working exactly as before, and the file is
invisible to older versions of Bunyi, so you can add it whenever you like.

Checksums also replace file size as the test for "already downloaded". Size
matching is precisely what a truncated file does, so a bad file could survive
on disk indefinitely. Now the digest decides.

**Manifest paths are treated as untrusted.** An entry that tried to escape the
model's folder — `../../` somewhere, an absolute path, a Windows drive letter
— is skipped and noted in the log rather than written. A manifest names its own
files, and a base URL is whatever was typed into Settings, so those names had
been trusted further than they deserved.
