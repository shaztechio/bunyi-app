Most of this came out of pointing Bunyi at a self-hosted model server for the
first time. The rest came out of finally looking at the window properly.

## The window

- **It looks designed now.** Panels have edges, the option rows line up, and the text box fills the space that used to sit empty below it.
- **Bunyi has its own colour.** Indigo in light and dark, instead of whichever accent you had set in System Settings.
- **Generate is readable when you cannot press it.** Generate and Stop are both solid and the same size, so swapping them moves nothing.
- **An empty window suggests something to try.** Each mode offers a couple of example prompts; click one and it fills the field.
- **History reads as a list.** The mode is a coloured tag, buttons highlight and say what they do, and the Trash is no longer red on every row.
- **Settings stopped reading like a README.** Every explanation sits beside the controls it explains, under real headings.
- **The Logs window lines up, and you can select from it.** Timestamps sit in their own column, and a drag selects across lines rather than one at a time.

## New

- **See everything you've generated.** A History tab lists every clip with its text and voice — play it, save a copy, copy the details, or move it to the Trash.
- **Every file remembers how it was made.** Text, voice, language and model are written inside the WAV, where ordinary audio tools can read them too.
- **Manage models without leaving the app.** Settings lists each downloaded model with its size and deletes it to the Trash.
- **Save model configurations.** Store the three sources under a name and switch between them, or reset them all in one click.
- **Download the models from Bunyi's own mirror.** One click points every mode at models.bunyi.app instead of Hugging Face — useful when the Hub is slow, and the difference between working and not where it is blocked. Same Apache-2.0 models, every file checksummed; Hugging Face stays the default.
- **Ask Bunyi whether it can actually run.** A stethoscope in the toolbar checks the model, disk space, memory, whether the source is answering, and whether the output folder is writable — and reports the passes too.
- **The same checks run before every generation**, so a problem is caught before a multi-gigabyte download rather than after it. Low memory warns rather than blocks.
- **Stop what you started.** Generate becomes Stop while anything is running, and Escape works too.
- **A Logs button and a Help button in the toolbar.** Both stay available while Bunyi is working, which is exactly when they are wanted.

## Fixed

- **Downloads looked stalled when they were fine.** Progress and stall detection now follow the bytes actually arriving.
- **Stopping a download meant starting over.** Files already fetched are kept; only what is missing downloads again.
- **Stopping a backup gave no sign it had worked.** Stop says it is finishing up now, and the progress bar no longer runs backwards as the backup gives up.
- **A half-downloaded model could look complete**, then fail to load with no explanation. An interrupted download is recognised as interrupted.
- **The script stayed editable while generating**, in every mode, even though the audio was already being made from what you typed.
- **Preset voice forgot your speaker.** Your choice is kept.
- **Generate is unavailable until a mode has what it needs** — a description for voice design, a clip for voice cloning — and says why on hover.
- **Playback broke up a second after a generation finished.** It lets the window settle before it starts.
- **Long generations dropped out mid-playback.** Working memory is handed back as soon as the file is written, and the clip is loaded before it plays rather than read as it goes.
- **Stopping a generation kept the memory it had been using.** All three endings release it now, not just the one that succeeded.
- **The playback bar rewound instead of resetting.** It snaps to zero.
- **Closing the window mid-run** stops the work first and closes once it has actually stopped.
- **The About panel** credits Shazron Abdullah and Bunyi contributors.

## For anyone self-hosting models

- **There are guides now.** [SELF-HOSTING.md](https://github.com/shaztechio/bunyi-app/blob/v1.1.0/SELF-HOSTING.md) walks through it from a standing start, including which hosts cannot work and why; [CACHING.md](https://github.com/shaztechio/bunyi-app/blob/v1.1.0/CACHING.md) covers putting the bucket behind a CDN.
- **Your server can publish checksums, and Bunyi will check them.** Add a `manifest.sha256` beside your `manifest.txt` — exactly what `shasum -a 256` prints — and every file is verified as it arrives. Servers without one keep working as before.
- **Checksums replace file size as the test for "already downloaded."** Matching sizes are precisely what a truncated file produces, so a bad file could otherwise survive on disk indefinitely.
- **Manifest paths are treated as untrusted.** An entry trying to escape the model's folder is skipped and logged rather than written.
- **Settings offered download commands that could not work.** Modes on your own server are named as such and left out, rather than producing an `hf download` line with a URL where a repo name belongs.
