A small release. The substantial part is what Bunyi does with memory when you
move between modes; the rest is polish, and a couple of things that make a
problem easier to describe.

## Memory

- **Bunyi lets go of a model as soon as you leave its mode.** Each mode uses its own, and a model can be several gigabytes — leaving one used to hold it until the next generate, which on a 16 GB Mac is often the difference between comfortable and swapping.
- **You can turn that off.** Settings → General → "Free memory when switching modes", on by default. Off keeps the model loaded so coming back to that mode is instant, and it is released the next time you generate in a *different* mode. Either way Bunyi never holds two models at once.

## The window

- **A gear in the toolbar opens Settings**, beside Doctor, Logs and Help — the same row, in the same order, as the Windows and Linux app.
- **Deleting a downloaded model is a trash icon now**, in Settings → Storage, the same one History uses. It says "Move to Trash", which is what it has always done.

## When something goes wrong

- **Bunyi says how long it took to start.** One line in the Logs, like `Startup: 1347 ms to first frame — before main 698 ms, first frame 650 ms.` The split is the useful part: the first figure is the system loading frameworks before any of Bunyi runs and nothing in the app can shrink it, the second is Bunyi's own.
- **Settings → General is documented.** Help had no General section at all, so neither the appearance setting nor the memory one was described anywhere.

Nothing else changed. Generation, playback, History, the model sources and
self-hosting all work exactly as they did in 1.1.0.
