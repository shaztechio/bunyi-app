## Critical current-main findings

1. **Global output gain is a streaming design constraint.** `spec/FEATURES.md:104` requires scanning the complete floating-point clip, leaving in-range/quiet audio unchanged, or applying one uniform `0.98/peak` attenuation if peak>1; reject NaN/infinity. .NET implements this in `apps/dotnet/src/Core/Qwen/DesignSpeechSynthesizer.cs:122`; clone calls it at `apps/dotnet/src/Core/Qwen/CloneSpeechSynthesizer.cs:142`; macOS uses `apps/macos/OutputLevel.swift:32` from `apps/macos/TTSEngine.swift:995`. Future peak cannot be known when an early chunk plays. Do not claim live/final identical amplitude, normalize each final chunk separately, or spool only prematurely clipped PCM16. Preserve original float PCM in a temporary spool, validate each chunk, track global peak, then write the final WAV with one uniform gain. Define an explicit separate protective preview-level policy in the spec; preview may sound different in level. Any NaN/infinity stops preview and rejects the whole take. Additional final spool pass needs cancellation and disk-error coverage.

2. **Budget exhaustion now fails rather than saving a truncated take.** `apps/dotnet/src/Core/Qwen/TalkerLoop.cs:290` throws `GenerationDidNotFinishException` at line 297 before final vocoder. Error text: `apps/dotnet/src/Core/Qwen/GenerationDidNotFinishException.cs:18`. `spec/FEATURES.md:92` forbids saving or auto-playing those takes; reliable macOS EOS reporting remains tracked in #224. Streaming necessarily may have played a prefix before discovering cap exhaustion: explicitly allow provisional preview in updated spec, immediately stop/discard queued audio on failure, publish no final WAV/History result, retain retry. Do not imply playback can be retroactively undone or that every semantically wrong take is detectable.

3. **Current state machine already has Checking and Finalizing.** ONNX finalizing begins at `apps/dotnet/src/Core/Engine/OnnxTtsEngine.cs:307`; error stage naming at line 344; `Publish` rejects late busy statuses once cancelled at line 509. macOS enters finalizing before float materialization (`apps/macos/TTSEngine.swift:966`). Extend these states rather than overwrite the recently added download/setup feedback.

4. **Voice Clone now performs blank-transcript transcription within one Generate operation.** `apps/dotnet/src/App/ViewModels/MainViewModel.cs:792`, `spec/FEATURES.md:510`. Snapshot streaming decision when Generate starts but preserve the eventual effective transcript in output metadata. UI operation cancellation wraps setup/transcription/engine; do not replace it with engine-only Stop.

## One inference run across all modes

Sentence regeneration is unsuitable as the common approach: Voice Design request only contains text/description/language (`apps/dotnet/src/Core/Qwen/DesignPrefill.cs:23`), and its description substitutes for identity (`:159`, `:183`). Every call builds new prefill (`apps/dotnet/src/Core/Qwen/DesignPipeline.cs:152`) and new KV/generated-code state (`apps/dotnet/src/Core/Qwen/TalkerLoop.cs:237`). Reusing a description does not guarantee the same voice. Keep one prefill, sampling state, all mode conditioning, KV cache and generated-code history; insert chunk decoding after complete codebooks at `apps/dotnet/src/Core/Qwen/TalkerLoop.cs:271`.

Candidate chunk experiments: 12 or 25 frames (~0.96/2 seconds at actual 12.5fps, `apps/dotnet/src/Core/Qwen/TalkerLoop.cs:174`). Decoder rolling context/right holdback must be verified for the actual export, not copied as a claim from another implementation. Streaming does not automatically reduce growing continuous talker KV memory.

## .NET decoder/engine integration

- `apps/dotnet/src/Core/Engine/ISpeechSynthesizer.cs:23` returns one PCM16 result; line 99 has only incremental frame counts. Add ordered run-scoped float-PCM chunk events/sink (offset, format, completion/error) without changing short-request synthesis behavior.
- `apps/dotnet/src/Core/Qwen/TalkerLoop.cs:303` currently calls vocoder once at end. `RunVocoder` at line 495 constructs `[1,groups,total]` codes; line 516 invokes codes-to-samples session. It exposes no cached decoder state. Rolling contextual re-decode is a feasibility experiment. Avoid growing-prefix re-decode as production design because work becomes quadratic.

First chunk must retain reference warmup without emitting reference speech; later chunks need generated context. Validate exact offsets/length/tail and no duplicate or missing samples.
- Reference resampling at `apps/dotnet/src/Core/Qwen/CloneSpeechSynthesizer.cs:130`; speaker/reference-code encoding at `apps/dotnet/src/Core/Qwen/ClonePipeline.cs:189`; ten-second export limit at line 75. Continuous inference reuses this setup once.
- Engine flow: synthesize `apps/dotnet/src/Core/Engine/OnnxTtsEngine.cs:286`, Finalizing/write line 307, release line 327; metadata/write methods line 453/472. Never report idle per chunk, or release working memory before actual producer completion.

## Playback/output

- .NET existing IAudioPlayer is complete-file Play(path), replacing prior playback (`apps/dotnet/src/Core/Audio/AudioPlayer.cs:32`, `:59`); reads full file at line 163. Add bounded PCM preview queue with real underrun/EOS distinction; Finished is also raised on Stop (190). Queue callback must be nonblocking, allocation-free and never touch inference.
- .NET HasResult hides controls while busy (`apps/dotnet/src/App/ViewModels/MainViewModel.cs:566`). Final autoplay at line 802 must be suppressed after streamed preview; Stop orchestration at 835 must stop the queue as well as existing operation cancellation. Preserve new setup/transcription state.
- macOS complete-file player creation `apps/macos/ContentView.swift:1007`, final autoplay 943/944, stopWork 951. Live queue needs a queue-capable audio implementation; preserve off-main loading and UI-stutter defenses in startPlayback at 1025.
- Only one player owns audible output across preview/final/History. Final synthesis/save can finish while queue still drains; do not replay final file automatically from start. Playback empty means buffering until explicit EOS, not finished. Audio-device failure should stop preview but allow successful final save; archival spooling and preview backpressure need separate lifetimes to avoid deadlock.
- Spool original float PCM privately, then apply one final gain and write valid 24kHz mono WAV/header and existing full-text/mode/voice metadata, publishing one final file/History item only after success. No partial WAVs in folder-based History. Delete temporary artifacts after stop/error and settled workers. Existing writer takes whole samples (`apps/dotnet/src/Core/Audio/WavWriter.cs:35`, `:47`); add incremental/finalizing writer instead of concatenating RIFF files.
