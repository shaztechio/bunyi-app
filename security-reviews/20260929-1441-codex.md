# Security review

I reviewed the repository's application, CLI, model download, backup, saved voice, worker, packaging, site, and CI trust boundaries. I found six code findings and one workflow finding. The code findings are fixed in this working tree; the workflow finding is documented only, as requested. The remaining risk is concentrated in user supplied local metadata and a mutable external workflow reference. This review is static and does not prove the absence of other vulnerabilities.

## Coverage

- **`apps/macos/`**: read `ModelSettings.swift`, `TTSEngine.swift`, `SettingsView.swift`, `VoiceLibrary.swift`, `SavedVoice.swift`, `BackupManager.swift`, `BackupFileTree.swift`, `HTTPFileDownloader.swift`, `ModelFileTransfer.swift`, `WhisperModelStore.swift`, and the CLI configuration, library, generation, and server endpoint/host files. Reviewed the project configuration, package lock, packaging scripts, and relevant tests. Other UI, audio, and inference files were searched for sensitive operations, with focused reads at matching call sites.
- **`apps/dotnet/`**: read `BackupManager.cs`, `VoiceLibrary.cs`, `ModelSource.cs`, `ModelDownloader.cs`, `ManifestPath.cs`, `DownloadedModels.cs`, `HttpFileDownloader.cs`, settings and CLI server files, and the affected tests. Reviewed package versions, packaging scripts, and tool entry points. Other UI, audio, and inference files were searched for file, process, network, and deserialization sinks, with focused reads at matching call sites.
- **`workers/downloads/`**: read the Worker entry point, permission contract, package manifest/lock, deployment configuration, and worker tests; checked the published file allowlist.
- **`tools/`, `docs/`, `spec/`, and `release-notes/`**: read the site builder, PR checker, release note tool, site template, shared feature and data format specifications, and relevant documentation. Static content and historical release prose received a lighter review than executable code.
- **`.github/workflows/`**: read workflow triggers, permissions, action references, secret use, and release/security jobs across the workflow files. No workflow file was changed.
- **Limits**: no macOS/Xcode runtime was available. The .NET projects could not restore NuGet assets because the configured package source was unreachable; therefore their tests and compilation could not run here. Worker tests require an unavailable `aws4fetch` installation. Large generated images, model data lists, and test fixtures were inspected by format or targeted search rather than line by line. Dependency vulnerability status was not checked against a live advisory service.

### SR-01 — macOS model repository path traversal

A configured Hub repository ID was interpolated into a local model path and remote URL without enforcing the expected `org/repo` form. A malformed value in persisted settings could make a download target or model lookup resolve outside the intended repository subtree. I added one ASCII component validator, applied it at CLI input and before download/lookup, and documented the accepted form in `spec/FEATURES.md`.

### SR-02 — archive repository selection before path validation

The .NET backup inspector accepted an archive entry's `models/` suffix as a repository before checking `..`, drive syntax, or separators. A crafted local archive could cause repository enumeration and existing-directory checks outside the models tree, although the later extraction check prevented writing such an entry. `RepoOf` now applies `ManifestPath.TryNormalize` first; a regression test covers traversal.

### SR-03 — .NET saved voice path traversal

`voices.json` supplied `fileName` directly to `Path.Combine`. A crafted local index could cause the app to read a recording outside `Voices`, and deletion could remove that external file. Loading now prunes invalid basenames; `ClipPath` rejects them, including at deletion. A regression test covers relative, absolute, drive, and backslash paths.

### SR-04 — macOS saved voice path traversal

The macOS voice library likewise used `fileName` from `voices.json` for playback and deletion. A crafted local index could point outside `Voices` within the app's accessible files. Loading now prunes unsafe names and strict deletion refuses them. The shared format specification and Swift format check were updated.

### SR-05 — macOS copyable command injection

Settings displayed an `hf download` line with the models folder inside double quotes and the repository ID unquoted. A path containing shell substitution, or a malformed repo ID, could run extra commands if a user copied the line into a shell. Settings now lists only validated repo IDs and POSIX shell quotes the destination folder.

### SR-06 — .NET copyable command injection

The .NET equivalent inserted a configured repo and models folder into a ready-to-run command. A malformed repo or quotes in the folder could change shell parsing after a user copied it. Command construction now uses the downloader's repo validation and quotes the folder for PowerShell on Windows or a POSIX shell on Linux. Invalid repos show an error in Settings, and a regression test covers both cases.

### SR-07 — mutable external reusable workflow

The security review job calls `shaztechio/multi-llm-security-review/.github/workflows/security-review.yml@main` while granting repository write permissions and `secrets: inherit`. A change to that external branch could execute with the caller's token and secrets on a later run. **Not fixed (workflow file)** under the review constraint. The exact fix is to replace `@main` with a reviewed full commit SHA, pin the corresponding `tool-ref` to that same SHA, pass only the needed secrets explicitly, and narrow job permissions to those the reviewed workflow requires.
