# Security review — 30 September 2026

This review swept the whole repository — both apps, the download Worker, the
specs, the tooling and every workflow — for injection, authn/authz flaws,
secrets in code, unsafe deserialization, path traversal, SSRF, weak crypto,
dependency risk and insecure defaults. It found two places in the .NET app
where a self-hosted model source URL's embedded credentials (HTTP basic auth
in `https://user:pass@host/...`) were rendered into user-visible strings — the
Doctor report (whose whole purpose is to be copied) and the downloaded-models
record. Both are fixed here with the same minimal `UriBuilder` strip the
engine's own display path already used; behavior and tests are unchanged. Two
further findings live in `.github/workflows/` — mutable action tags on 22
`uses:` lines across seven workflows, and `persist-credentials: true` on the
two release checkouts — and are reported but not fixed, because this token
may not modify workflow files; the exact fix for each is described below. The
overall posture is strong: release workflows already pin full commit SHAs,
the downloads Worker allowlists exact object keys, checks a Durable-Object
killswitch before every signing, and strips caller-controlled query from
signed URLs, and the app's manifest path rules reject traversal outright.

### F1 — Credentials leaked into the Doctor report (High, Fixed)

`Doctor.SourceFinding` names the configured model source in its finding text.
For a self-hosted source, the source *is* the URL, and a self-hosted URL can
legitimately carry HTTP basic-auth credentials
(`https://user:pass@host/model/`). The code put `url.Url.AbsoluteUri` into
that text verbatim, and `DoctorReport.Describe()` exists "for the Logs and
the clipboard" — so the credential could land in both the app's log store and
the user's clipboard with one "copy report" action.

**Impact:** a user who self-hosts their model server behind basic auth and
runs Doctor on demand gets their server password copied to the clipboard,
where clipboard managers, cloud sync and pasted bug reports can carry it
further. The Doctor report is explicitly designed to be shared.

**What changed:** the display string now strips userinfo, query and fragment
via `UriBuilder` before rendering — the same pattern `OnnxTtsEngine.SourceName`
(OnnxTtsEngine.cs:667) already used for the identical situation. The URL
Doctor actually probes (`Doctor.ProbeUriFor`) is untouched and still carries
the credentials, because it is fetched, not displayed; every other Doctor
behavior is unchanged.

### F2 — Credentials in the downloaded-model record (High, Fixed)

Same class of leak at a second boundary. `ModelDownloader.DownloadAssetsAsync`
stamps each finished download with a `Source` string built from
`url.Url.AbsoluteUri`, which the App surfaces in the downloaded-models list
and which flows into logs.

**Impact:** the self-hosted URL's password would be displayed wherever the
downloaded model's source is named, and re-shown anywhere that string is
logged or persisted.

**What changed:** the same minimal `UriBuilder` strip as F1, matching the
existing pattern in the engine. Planning, disk-space precheck, SHA-256
verification, resume and reuse logic are all untouched.

### F3 — Actions referenced by mutable tags (High, Not fixed — workflow file)

The 22 `uses:` lines above reference `actions/*` by `@v` tag. A tag is a
mutable pointer: whoever controls the action repository can move it, and
GitHub will run the new commit in these workflows with whatever permissions
and secrets the job has. The two *release* workflows (`release.yml`,
`dotnet-release.yml`) already pin full commit SHAs — the signing paths are
protected. These seven are not:

- `download-worker.yml` deploys the model-download Worker, which has the R2
  signing credentials in scope — the highest-value target in the set.
- `pages.yml` builds and deploys the public site.
- `dotnet.yml`, `macos.yml`, `pull-request.yml`, `model-mirror-smoke.yml`,
  `linux-installer-check.yml` run the test/build matrix, several on
  `pull_request`.

**Impact:** a compromised or re-registered action account could run arbitrary
code inside CI — most seriously in `download-worker.yml`, where a stolen run
could deploy an attacker-controlled signer or exfiltrate the R2 keys.

**Exact fix:** pin every one of these lines to the full 40-character commit
SHA currently behind the tag, keeping the tag as a trailing comment exactly
as `release.yml` and `dotnet-release.yml` already do:

```yaml
uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7
```

Resolve each current SHA with
`git ls-remote https://github.com/actions/<name>.git refs/tags/v<major>`
(or the API equivalent) at the time of the fix. Add
`zizmor`/`check-pull-request`-style enforcement later if desired, but the pin
itself is the fix.

**Why left:** the token publishing this change is not allowed to push
workflow files.

### F4 — `persist-credentials: true` on the release checkouts (Medium, Not fixed — workflow file)

Both release workflows check out with `persist-credentials: true` because the
version-bump commit/tag push happens later in the same job. That leaves the
`GITHUB_TOKEN` — with `contents: write` — written into the workspace's
`.git/config` for the remainder of a long build-and-sign job. Every subsequent
step, including every release script, can read it, and any step that goes
astray (a script that fetches a remote URL, a log that dumps config) can
exfiltrate a repo-write credential.

**Impact:** moderate. The later steps are first-party scripts and SHA-pinned
actions, so this widens the blast radius of a future mistake rather than
being exploitable today — which is why it is Medium and F3 is High.

**Exact fix:** check out for the build with `persist-credentials: false`, and
make the version-bump/tag push its own final step that authenticates just for
that one command — for example, after the build job, a short job that checks
out (no credential persistence), runs the version bump, and pushes with the
token passed only to that step:

```yaml
- uses: actions/checkout@<full-sha> # v7
  with:
    persist-credentials: false
- run: |
    git config user.name "github-actions[bot]"
    git config user.email "github-actions[bot]@users.noreply.github.com"
    # ... bump, commit ...
    git push "https://x-access-token:${{ github.token }}@github.com/${{ github.repository }}.git" "v${VERSION}"
```

so the credential exists for one command instead of two hours of build.

**Why left:** the token publishing this change is not allowed to push
workflow files.

## Verified sound (no finding)

Checked and deliberately not changed, so a later reviewer does not re-chase
them:

- **Doctor's probe URL keeps credentials by design** (`Doctor.ProbeUriFor`)
  — it is HEADed for reachability, never displayed.
- **`ModelDownloader.Slug`** builds the on-disk folder name from host +
  absolute path only; userinfo, query and fragment can never enter a
  filesystem name, and non-safe characters are replaced.
- **`OnnxTtsEngine.SourceName`** and **`CommandDispatcher.SourceText`**
  (`CliLog.Redact`) — the app's other two source-name boundaries were already
  stripping credentials; F1/F2 were the two missing sites.
- **Manifest path handling** — `ManifestPath`/`ManifestParser` enforce the
  DATA-FORMATS rules against traversal and absolute paths before any path
  becomes a write destination.
- **Workers/downloads** — published-key allowlist with digests, method-specific
  signing, caller query/credentials never forwarded, fresh permission check
  per request, no KV fallback, fail-closed configuration, staging isolation.
- **No secrets in code** — the PostHog `phc_` token is a public client key by
  design; R2 Cloudflare account IDs are not secrets; only credential *names*
  appear in workflow docs.
- **NuGet/npm supply chain** — `<clear/>` NuGet config, exact CPM versions,
  exactly-pinned npm dependencies.
- **Release workflows** — full-SHA action pins, tag/dispatch-only triggers
  (never fork `pull_request`), job-level `permissions`, credential
  non-persistence where not needed, strict version-input regexes, untrusted
  input passed via `env:` rather than interpolated into shell.
