# Security review

This review found one model restore boundary issue and two release workflow command injection issues. The restore issue is fixed in both native implementations: archives with symbolic links or other special entries are rejected before repositories are merged. The workflow issues remain open because this review was instructed not to edit `.github/workflows/`; both require moving dispatch inputs into environment variables before shell evaluation. No embedded credential was found in the reviewed source and configuration. This was a static review with focused execution checks, not a live dependency advisory audit.

### SR-01 — symbolic links in restored model archives

The macOS restore extracted a user-selected ZIP and moved its repository tree into Models without checking for symbolic links. A link in that tree could make later model reads or downloads follow a path outside Models. I added a recursive regular-file-and-directory check before any repository merge. The .NET archive inspector now rejects ZIP entries marked as Unix links or other special types, keeping the shared archive rule consistent. The format specification and focused regression checks were updated. The Swift check passed; the .NET regression test could not run in this environment.

### SR-02 — macOS release input shell injection

The `workflow_dispatch` `version` string is inserted directly into a Bash assignment before validation. Shell substitution in that input is evaluated with the release job's token and signing environment. **Not fixed (workflow file).** Set `REQUESTED_VERSION: ${{ inputs.version }}` in the step's `env`, use `requested="$REQUESTED_VERSION"`, and pass `inputs.bump` through an environment variable too. Validate the resulting version with a fully anchored numeric pattern before using it in file edits, tags, or output.

### SR-03 — .NET release input shell injection

The `workflow_dispatch` `version` string appears directly in both a Bash condition and assignment in the version job. Shell substitution is evaluated before the subsequent version check, and the job has repository write access. **Not fixed (workflow file).** Pass `inputs.version` and `inputs.bump` through step environment variables, refer only to the quoted variables in Bash, and use a fully anchored numeric version check before writing outputs or tags.
