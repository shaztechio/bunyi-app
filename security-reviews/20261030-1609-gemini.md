# Security Review

This review audited the entire `bunyi-app` repository across the macOS Swift/MLX desktop and CLI app (`apps/macos/`), the Windows/Linux .NET 10 and Avalonia desktop and CLI app (`apps/dotnet/`), the Cloudflare R2 presigning download Worker (`workers/downloads/`), the documentation site and release tooling (`docs/`, `tools/`, `spec/`), and the GitHub Actions CI/CD workflows (`.github/workflows/`). We identified five Medium-severity issues: an integer overflow / negative ZIP64 entry size bypass in `.NET` backup archive inspection, unredacted self-hosted model URLs carrying credentials or query tokens in CLI JSON responses, exception messages, and desktop logs, overly permissive (`0644`) file permissions on persisted settings, model configurations, and logs on Unix systems, an exact-string comparison in macOS built-in mirror detection that allowed trailing slashes or uppercase hostnames to bypass mandatory `manifest.sha256` verification, and mutable action tag references and persisted checkout credentials in `.github/workflows/`. All four application/code findings have been fixed in this PR; the workflow finding is documented with an exact remediation as required by the review constraints.

## Detailed Findings

### BUNYI-SEC-01 — Signed integer overflow and negative `ZipArchiveEntry.Length` in backup inspection bypasses disk free-space check

- **Severity:** Medium (`CWE-190`, `CWE-409`)
- **Location:** `apps/dotnet/src/Core/BackupManager.cs:173`
- **Status:** Fixed
- **Description:** `BackupManager.Inspect` accumulates `bytes += entry.Length` in an `unchecked` context, and `RestoreAsync` computes `total = archive.Entries.Where(...).Sum(e => e.Length)` before calling `EnsureRoom(total, FreeSpaceOf(modelsFolder))`. In .NET's `ZipArchiveEntry`, `entry.Length` is a signed `long` populated from the 64-bit uncompressed size field of a ZIP64 central directory header. If a crafted ZIP64 archive sets the high bit on a 0-byte dummy entry (`entry.Length < 0`), it offsets positive `entry.Length` values on subsequent entries so that `bytes` and `total` evaluate to `0` or a negative value. Because `CopyAsync` only checks `if (copied > limit)` inside its `while ((read = await source.ReadAsync(...)) > 0)` loop, a 0-byte stream never enters the loop to fail the negative `limit`, while a second entry declaring tens of gigabytes is extracted without being stopped by `EnsureRoom`. Similarly, positive `entry.Length` values whose sum exceeds `long.MaxValue` wrap `bytes` to a negative value in `Inspect`.
- **Impact:** A crafted backup archive can bypass the pre-extraction free-space check (`EnsureRoom`) and fill the target disk during restore, or report a negative total byte count during inspection.
- **Change made:** Updated `BackupManager.Inspect` in `apps/dotnet/src/Core/BackupManager.cs` to reject any model entry where `entry.Length < 0 || bytes > long.MaxValue - entry.Length` with `InvalidDataException("The backup declares an invalid file size and cannot be restored safely.")`.

### BUNYI-SEC-02 — Self-hosted model URLs carrying credentials or query tokens are leaked in CLI output, exception messages, and desktop logs

- **Severity:** Medium (`CWE-532`, `CWE-200`)
- **Location:** `apps/macos/CLI/ModelCommand.swift:222` (also `apps/macos/CLI/ModelCommand.swift:321,397`, `apps/macos/CLI/SpeakersCommand.swift:84`, `apps/macos/CLI/ConfigurationCommand.swift:58`, `apps/macos/Doctor.swift:300`, `apps/dotnet/src/Cli/Commands/CommandDispatcher.cs:284`, `apps/dotnet/src/Core/Models/ModelDownloader.cs:190,581`, `apps/dotnet/src/Core/Diagnostics/LogStore.cs:117`)
- **Status:** Fixed
- **Description:** Several paths across both platforms emitted or logged self-hosted model source URLs without redacting embedded HTTP basic-auth credentials (`https://user:pass@host/...`), query tokens (`?token=...`), or fragments:
  1. In `apps/macos/CLI/`, `ModelCommand.swift` (`models.download`, `models.remove`, `models.status`), `SpeakersCommand.swift` (`speakers`), and `ConfigurationCommand.swift` (`config.list`, `config.get`, `config.set`) returned or logged `mode.effectiveRepoID` / `settings.modelSource` without passing it through `PrivacyRedactor.modelSource(...)`, and `Doctor.swift` fell back to raw `base.absoluteString` when `base.host` was nil.
  2. In `apps/dotnet/`, `CommandDispatcher.SetConfig` returned the raw `value` on `config.set modelSource.*` (whereas `config.list` and `config.get` redacted it), `ModelDownloader.ChecksumsRequired` and `ModelDownloader.TooLarge` interpolated raw `Uri` instances (including `UserInfo`, `Query`, and `Fragment`) into `InvalidDataException` messages, and `LogStore.Log` in `Bunyi.Core` (used by the desktop app and `FileMirror`) recorded messages without redacting URL credentials/queries or `Authorization`/`Bearer` headers.
- **Impact:** Users who configure a private self-hosted model mirror with basic-auth credentials or presigned query parameters can have those credentials leaked into CLI JSON output (often captured by agent harnesses or CI logs), UI status/error messages, and on-disk log files.
- **Change made:** Applied `PrivacyRedactor.modelSource(...)` in `apps/macos/CLI/ModelCommand.swift`, `apps/macos/CLI/SpeakersCommand.swift`, `apps/macos/CLI/ConfigurationCommand.swift`, and `apps/macos/Doctor.swift`; redacted `modelSource.*` return values in `apps/dotnet/src/Cli/Commands/CommandDispatcher.cs`; stripped `UserName`, `Password`, `Query`, and `Fragment` in `ModelDownloader.ChecksumsRequired` and `ModelDownloader.TooLarge` in `apps/dotnet/src/Core/Models/ModelDownloader.cs`; and added URL and `Authorization`/`Bearer` redaction to `LogStore.Log` in `apps/dotnet/src/Core/Diagnostics/LogStore.cs` with unit tests in `LogStoreTests.cs` and `ModelDownloaderTests.cs`.

### BUNYI-SEC-03 — Persisted settings, model configurations, and log files containing self-hosted model URLs and credentials are created with world-readable permissions on Unix

- **Severity:** Medium (`CWE-276`, `CWE-732`)
- **Location:** `apps/dotnet/src/Core/Settings/SettingsStore.cs:117` (also `apps/dotnet/src/Core/Settings/SettingsStore.cs:138`, `apps/dotnet/src/Core/Settings/ModelConfigLibrary.cs:350`, `apps/dotnet/src/Core/Diagnostics/LogStore.cs:195`, `apps/dotnet/src/Cli/Protocol/CliOutput.cs:96`, `apps/macos/ModelConfigLibrary.swift:114,169`)
- **Status:** Fixed
- **Description:** `settings.json` and `configs.json` store the user's raw self-hosted model URLs (which must retain any HTTP basic-auth credentials or query tokens to authenticate downloads), and `bunyi-*.log` / `bunyi-cli.log` store runtime diagnostics. While `CLISettingsStore.swift` and `LogStore.swift` on macOS set `0700` directory and `0600` file permissions, `SettingsStore.cs`, `ModelConfigLibrary.cs`, `LogStore.cs`, and `CliOutput.cs` on Linux (.NET) and `ModelConfigLibrary.swift` on macOS created these files using the process's default `umask` (typically `0644` world-readable).
- **Impact:** On a shared or multi-user Linux or macOS system, other local users or unprivileged processes could read `~/.config/Bunyi/settings.json`, `~/.config/Bunyi/ModelConfigs/configs.json`, `~/Library/Application Support/Bunyi/ModelConfigs/configs.json`, and the log files to harvest self-hosted server credentials and local activity logs.
- **Change made:** Set `UnixFileMode.UserRead | UnixFileMode.UserWrite` (`0600`) on temporary settings/config files before moving them into place in `SettingsStore.cs` and `ModelConfigLibrary.cs` and on log files in `LogStore.cs` and `CliOutput.cs` when `!OperatingSystem.IsWindows()`, and set `.posixPermissions: 0o700` on `ModelConfigs` and `0o600` on `configs.json` in `apps/macos/ModelConfigLibrary.swift`.

### BUNYI-SEC-04 — Built-in Bunyi mirror check on macOS uses exact string equality, allowing trailing slashes or uppercase hostnames to bypass mandatory `manifest.sha256` verification

- **Severity:** Medium (`CWE-354`, `CWE-345`)
- **Location:** `apps/macos/ModelSettings.swift:100` (and `apps/macos/TTSEngine.swift:490,642`)
- **Status:** Fixed
- **Description:** Per `spec/FEATURES.md §3b`, the built-in Bunyi mirror (`models.bunyi.app`) must serve `manifest.sha256` with a digest for every file and must never fall back to an unverified file list. While .NET's `ModelConfigLibrary.IsBunyiMirrorUrl` trims trailing slashes and compares case-insensitively against all built-in mirror URLs, macOS's `TTSMode.isUsingBuiltInMirror(_ source: URL)` checked `source.absoluteString == bunyiMirrorURL.absoluteString && effectiveRepoID == source.absoluteString`. If a mirror URL was configured with a trailing slash (e.g. `https://models.bunyi.app/customvoice/`), an uppercase hostname (`https://MODELS.bunyi.app/customvoice`), or another mode's mirror URL, `isUsingBuiltInMirror` returned `false` and `TTSEngine` allowed unverified downloads without `manifest.sha256`.
- **Impact:** A trailing slash or uppercase hostname in a configured `models.bunyi.app` URL on macOS silently disabled mandatory SHA-256 manifest enforcement, allowing a network or mirror fault/tampering to downgrade to unverified model files.
- **Change made:** Added `TTSMode.isBunyiMirrorURL(_ url: URL) -> Bool` in `apps/macos/ModelSettings.swift` that strips trailing slashes and compares case-insensitively against all built-in mirror endpoints, normalized `isUsingBuiltInMirror`, and updated `apps/macos/TTSEngine.swift` to pass `requireChecksums: TTSMode.isBunyiMirrorURL(...)`.

### BUNYI-SEC-05 — GitHub Actions workflows pin actions to mutable version tags/branches instead of full commit SHAs and persist checkout credentials across release jobs

- **Severity:** Medium (`CWE-829`, `CWE-250`)
- **Location:** `.github/workflows/release.yml:36` (also `.github/workflows/dotnet-release.yml:87`, `.github/workflows/dotnet.yml:40`, `.github/workflows/macos.yml:35`, `.github/workflows/download-worker.yml:27`, `.github/workflows/linux-installer-check.yml:42`, `.github/workflows/model-mirror-smoke.yml:48`, `.github/workflows/pages.yml:35`, `.github/workflows/pull-request.yml:29`, `.github/workflows/security-review.yml:25`)
- **Status:** Not fixed (workflow file)
- **Description:** Across `.github/workflows/*.yml`, GitHub Actions steps reference mutable major tags or branch names (`actions/checkout@v6`, `actions/setup-dotnet@v5`, `actions/setup-node@v6`, `actions/cache@v5`, `actions/upload-artifact@v7`, `actions/download-artifact@v8`, `actions/configure-pages@v5`, `actions/upload-pages-artifact@v4`, `actions/deploy-pages@v5`, `shazron/security-review-action@main`) rather than immutable 40-character commit SHAs. In addition, `.github/workflows/release.yml` (line 36) and `.github/workflows/dotnet-release.yml` (line 87) pass `persist-credentials: true` to `actions/checkout@v6`, leaving a `contents: write` token in `.git/config` for the duration of the build, test, and packaging steps.
- **Impact:** If an upstream action tag or branch is retargeted or compromised, workflows with write permissions or release signing secrets (`APPLE_CERTIFICATE_P12`, `CLOUDFLARE_API_TOKEN`, `CERTUM_CLOUD_SECRET`, `GITHUB_TOKEN`) would execute untrusted code; persisting git credentials across build/test steps exposes `contents: write` push access to every tool and dependency invoked during the job.
- **Why left & exact fix:** Per review instructions, files under `.github/workflows/` must not be modified. To fix:
  1. Pin every `uses:` reference in `.github/workflows/*.yml` to its full 40-character commit SHA with a version comment (for example, `uses: actions/checkout@<40-char-sha> # v6`), and pin `shazron/security-review-action` and its `tool-ref` input in `.github/workflows/security-review.yml` to a reviewed commit SHA.
  2. Set `persist-credentials: false` on `actions/checkout` in `.github/workflows/release.yml` and `.github/workflows/dotnet-release.yml`, and authenticate the version-bump `git push` step explicitly using a step-scoped `GITHUB_TOKEN` credential helper or split the version-bump commit/tag creation into its own minimal job with `contents: write` while keeping build/sign jobs `contents: read`.
