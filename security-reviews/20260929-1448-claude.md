# Security review — bunyi-app (2026-09-29)

## Summary

This review covered the macOS app (Swift/MLX), the Windows and Linux app (.NET/Avalonia: Core, CLI, App, tools, packaging), the Cloudflare download Worker, the site and release tooling, and every GitHub Actions workflow. Nothing Critical or High was found. The security boundaries that matter most hold up:

- Manifest and zip entry paths are normalised and contained (`ManifestPath.TryResolve`, `safeRelativePath`).
- The local CLI server listens only on a 0700 directory with a 0600 socket, checks the peer's uid, or uses `CurrentUserOnly` pipes on Windows.
- Deserialisation is typed JSON only.
- No process launch goes through a shell.
- Downloads with a published digest are verified.
- Release signing is kept away from `pull_request` triggers.
- The Worker uses an exact allowlist of object keys.

The real weaknesses are in data that travels between machines:

- **`voices.json`:** a crafted `fileName` could make "Delete voice" remove any file the user can write. Found and fixed on both platforms.
- **macOS backup zips:** symlinks in a backup were moved into the live models folder on restore. Fixed.
- **WAV metadata parser:** an integer overflow could hang or crash History. Fixed.
- **macOS CLI server:** a malformed local request could crash it. Fixed.

The remaining findings are Low or design-level hardening and are left for the maintainer. They include plain-`http://` model sources, unpinned Hugging Face and Whisper downloads, and log redaction gaps. Two workflow issues are reported but not changed, because workflow files are out of bounds for this review.

**Tests were not run.** This sandbox refused `dotnet test` and has no Swift toolchain. Every change was checked by reading it against all of its callers and the existing tests; no test asserts the old behaviour.

### BUNYI-01: saved-voice `fileName` path traversal (.NET), Medium, CWE-22. Fixed.

- **Description:** `VoiceLibrary.ClipPath` and `Load` passed the `fileName` from `voices.json` straight to `Path.Combine`. An absolute path, or a value containing `../`, resolves outside the Voices folder. The spec says voice libraries move between apps and machines.
- **Impact:** a crafted `voices.json` (for example `"fileName": "/home/u/.ssh/id_ed25519"`) passes the "clip exists" check. "Delete voice" in the GUI or the CLI (`voices remove`) then calls `File.Delete` on that file. The same path is also read as clone reference audio.
- **Change:** added `IsPlainFileName`, which accepts only a bare name with no `/`, `\` or `:`, and not `.` or `..`. `Load` now drops entries that fail it, and `ClipPath` throws for them. Bunyi only ever writes `<uuid>.wav`, so no legitimate entry is affected.

### BUNYI-02: saved-voice `fileName` path traversal (macOS), Medium, CWE-22. Fixed.

- **Description:** `audioURL(for:)` appended `voice.fileName` unchecked, and `deleteStrict` removes that URL.
- **Impact:** the same as BUNYI-01, limited to what the sandbox can reach.
- **Change:** `load()` now keeps only entries whose `fileName` is a bare name. This is the same rule as .NET, so both platforms behave the same.

### BUNYI-03: backup restore trusts symlinks (macOS), Medium, CWE-59. Fixed.

- **Description:** `ditto -xk` recreates symlinks stored in the archive. `performRestore` then moves whole repo folders, including any links inside them, into the live models folder.
- **Impact:** a crafted backup can plant a link such as `speech_tokenizer -> ~/Documents`. The next download follows it: `ModelFileTransfer` removes and replaces `destination`, and `.incomplete` files are deleted, all outside the models folder. The unsandboxed CLI makes this worse.
- **Change:** after extraction and before anything is moved, `rejectSymlinks(in:)` walks the tree. Any symlink aborts the restore with a new `BackupError.unsafeEntry`. Bunyi's own backups never contain symlinks, because `zip` dereferences them (see BUNYI-17).
- **.NET:** already safe, because `ZipArchive` does not create links and entries are normalised.

### BUNYI-04: `http://` model sources accepted, Medium, CWE-319 / CWE-494. Not fixed.

- **Description:**
  - .NET: `ModelSource.Parse` (lines 57-58) accepts `http://` base URLs.
  - macOS: `ModelSettings.swift:68` does the same, though ATS blocks cleartext in the GUI.
- **Impact:** the manifest, its SHA-256 digests and the ONNX/`.npy` payloads all travel in cleartext. An attacker on the network path can replace the weights and the matching digests together, and native onnxruntime then parses the result.
- **Why left:** `SELF-HOSTING.md` documents `http://` for LAN mirrors, so blocking it changes a supported feature.
- **Recommended fix:** allow `http` only when `url.IsLoopback` (or behind an explicit opt-in), otherwise reject it with a clear message.

### BUNYI-05: WAV metadata integer overflow, Low, CWE-190 / CWE-835. Fixed.

- **Description:** `FindInfoField` cast the 32-bit sub-chunk size to `int` before the bounds check. A size of `0xFFFFFFF8` becomes −8, passes `body + size > end`, and resets `position` to itself.
- **Impact:** one crafted `.wav` in the Outputs folder (the spec says these travel between machines) hangs History and `history list`. If the chunk id is `ICMT`, it throws an uncaught `ArgumentOutOfRangeException` instead.
- **Change:** the bound is now checked on the unsigned value widened to `long`, and the size is cast to `int` only after it passes. The outer `FindComment` loop already promoted `int + uint` to `long`.

### BUNYI-06: CLI server crash on a malformed request (macOS), Low, CWE-20 / CWE-617. Fixed.

- **Description:** `ServerHost.execute` and `preload`, and `ModelCommand` download, verify and remove, used `request.value("mode")!`. The server does not re-run the client-side parser.
- **Impact:** any same-user process writing to the socket can crash the resident server by leaving out `mode`. An unknown mode also silently became `preset`.
- **Change:** added `ModelCommand.requiredMode(_:)`. It throws `invalid_arguments` when `mode` is missing and validates it with `CLICommandParser.mode`. All five force-unwraps now use it.

### BUNYI-07: unpinned third-party model downloads, Low, CWE-494. Not fixed.

- **Description:**
  - .NET: `ModelDownloader.cs:506` fetches from `resolve/main`.
  - .NET: `ModelLayout.cs:271` lists `ggml-base.bin` with no SHA-256. macOS already pins Whisper.
  - macOS: `TTSEngine.swift:1026` fetches `tokenizer.json` from a third-party repo at `resolve/main` with no digest.
- **Impact:** if the upstream repository changes or is compromised, the change is loaded into native parsers without any check.
- **Recommended fix:** pin a commit (`resolve/<sha>/`) and add `Sha256:` or a `ManifestEntry` digest. Needs the maintainer to supply the published hashes.

### BUNYI-08: mirror checksum fallback, Low, CWE-757. Not fixed.

- **Description:** a 404 or network error on `manifest.sha256` quietly falls back to `manifest.txt`, or to the built-in list, with no digests (`ModelDownloader.cs:126-150`).
- **Recommended fix:** for URLs in `ModelConfigLibrary.BunyiMirror`, require `manifest.sha256` and a digest on every entry, and fail otherwise.
- **Why left:** it is a policy change that needs testing against the live mirror.

### BUNYI-09: predictable Linux server directory, Low, CWE-377 / CWE-400. Not fixed.

- **Description:** the directory is `Path.GetTempPath()/bunyi-<hash(uid, data root, config path)>`, and every input is guessable.
- **Impact:** another local user can create the directory first. The ownership check fails closed (so the endpoint is not hijacked), but `/tmp` is sticky, so `--require-server` and `--detach` break until reboot.
- **Recommended fix:** use `$XDG_RUNTIME_DIR` when it is set and absolute, and fall back to the temp dir otherwise.
- **Why left:** it moves the endpoint location, which needs a cross-version compatibility decision.

### BUNYI-10: Windows pipe-instance exhaustion, Low, CWE-770. Not fixed.

- **Description:** `new NamedPipeServerStream(..., 32, ...)` sits outside the try block in the accept loop.
- **Impact:** a 33rd concurrent client (same user) throws `IOException`, which ends the server and cancels its jobs.
- **Recommended fix:** catch `IOException` around the constructor, wait about 100 ms and continue. Optionally cap concurrency with a `SemaphoreSlim` on both platforms.
- **Why left:** Windows behaviour can't be verified here.

### BUNYI-11: Windows search-path hijacking, Low, CWE-427. Not fixed.

- **Description:**
  - `WebLink.cs:63` and `FileReveal.cs:58` start a bare `explorer.exe` with `UseShellExecute=false`.
  - No `SetDllDirectory("")` or `SetDefaultDllDirectories` call exists, so the CUDA edition's separately installed cuDNN/cuBLAS DLLs are found through a search order that includes the current directory.
  - The background server inherits the caller's working directory (`ServerClient.cs:87`).
- **Impact:** running `bunyi` inside an attacker-controlled folder can load a planted binary.
- **Recommended fix:** use `Path.Combine(Environment.GetFolderPath(SpecialFolder.Windows), "explorer.exe")`, call `SetDllDirectoryW("")` at the start of both `Main`s, and start the server with `WorkingDirectory = AppContext.BaseDirectory`.
- **Why left:** the tests assert the bare `explorer.exe`, and the change can't be validated on Windows here.

### BUNYI-12 and BUNYI-13: macOS server robustness, Low, CWE-400 / CWE-755. Not fixed.

- **Description:**
  - `ServerWire.read` re-arms its 5 s poll timeout for every byte, and there is no connection cap.
  - `ServerSocket.accept` rethrows `ECONNABORTED`, `EMFILE` and peer-check failures, and the accept loop then calls `requestStop()`.
- **Impact:** a same-user process (or root) can stall or stop the server.
- **Recommended fix:** use one overall deadline per message, and cap connections at about 16. In `accept`, close and continue on per-connection errors, and back off on `EMFILE`/`ENFILE`.
- **Why left:** the concurrency changes can't be compiled or tested without a macOS toolchain.

### BUNYI-14: notary password on the command line, Low, CWE-214. Not fixed.

- **Description:** `sign-and-notarize.sh:133` and `sign-and-notarize-cli.sh:87` pass `--password "$BUNYI_APP_PASSWORD"` to `notarytool`. A comment says the password is never put on the command line.
- **Impact:** the password is visible to the same user in `ps` for the whole `--wait`. On CI the runner is single-tenant, so the practical risk is low.
- **Recommended fix:** use an App Store Connect API key (`--key/--key-id/--issuer`) or `--keychain-profile`. At minimum, correct the comment.
- **Why left:** it needs new secrets.

### BUNYI-15: log redaction gaps, Low, CWE-532. Not fixed.

- **Description:**
  - `TTSEngine.swift:1657,1677` log `String(describing: error)`. For `DownloadServiceError` and `URLError`, that includes the full source URL (credentials and signed query strings).
  - `PrivacyRedactor.swift:21-23` returns the input unchanged when `URLComponents` fails to parse it.
- **Recommended fix:** log `localizedDescription` plus `PrivacyRedactor.modelSource(...)`, and make the redactor fail closed (`"[redacted URL]"` when the input contains `@`, `?` or `#`).
- **Why left:** behaviour change in logs, and no Swift toolchain here to run `PrivacyRedactorChecks`.

### BUNYI-16: sensitive text in the system log, Low, CWE-532. Not fixed.

- **Description:** `LogStore.swift:62` writes every message to OSLog with `privacy: .public`. The GUI logs the reference transcript (`TTSEngine.swift:1956`) and absolute home paths.
- **Impact:** the user's spoken words persist in the unified log and in sysdiagnose.
- **Recommended fix:** log `"Reference transcription completed"`, as the CLI already does, or use `.private` for the OSLog copy.
- **Why left:** it is a product decision about diagnostics.

### BUNYI-17: backup `zip` dereferences symlinks, Low, CWE-59. Not fixed.

- **Description:** `/usr/bin/zip` without `-y` stores the target of any symlink found in the models folder.
- **Why left:** BUNYI-03 already stops a backup from planting links. The only links left are ones the user created, where following them is the expected behaviour. Adding `-y` would make Bunyi's own backups contain links, which restore now rejects.

### BUNYI-18: unbounded restore size, Low, CWE-409. Not fixed.

- **Description:** neither platform checks the uncompressed size or free space before extracting, and macOS also copies the zip first.
- **Recommended fix:** sum the entry lengths (.NET `ZipArchive`, macOS `zipinfo -t`) and compare against free space, and stop writing any entry that exceeds its declared length.

### BUNYI-19: unbounded parsers, Low, CWE-400 / CWE-789. Not fixed.

- **Description:**
  - `ModelDownloader.cs:526` reads the manifest body with no limit.
  - `NpyArray.cs:199,207,241` accepts headers up to 2 GiB and negative dimensions, and does not check the data size against the file length.
  - `ReferenceAudio.cs:140` allocates a buffer the size of the whole decoded file.
- **Impact:** memory exhaustion only. The view accessor bounds-checks, so there is no memory corruption.
- **Recommended fix:** cap the manifest (about 1 MiB) and the header (about 64 KiB), reject negative dimensions, and cap reference audio at a few minutes.

### BUNYI-20: copy-paste `hf download` command, Low, CWE-78. Not fixed.

- **Description:** `DownloadedModels.cs:131-132` interpolates `repo.Id` from settings or `configs.json` into a shell command that Settings shows for the user to copy, with no validation.
- **Recommended fix:** validate the id with the existing `ValidatedRepoPath` (return null if invalid) and single-quote the destination.
- **Why left:** it is only displayed, never executed, and the input comes from the user's own configuration.

### BUNYI-21: third-party script without CSP or SRI, Low, CWE-829. Not fixed.

- **Description:** the PostHog loader in `docs/index.html:354-364` injects `https://t.shaztech.io/static/array.js` with no `integrity` attribute, and the page has no Content-Security-Policy.
- **Impact:** whoever controls that proxy can run script on the page that hands out installer links.
- **Recommended fix:** a CSP `<meta>` restricting `script-src` to `'self'`, `t.shaztech.io` and hashes of the three inline scripts, or self-host a pinned `array.js` with SRI.
- **Why left:** the inline-script hashes must be regenerated whenever the page changes, so the maintainer should adopt this deliberately.

### BUNYI-22: workflow input interpolated into shell, Low, CWE-78. Not fixed (workflow file).

- **Description:**
  - `release.yml:87,93,97` and `dotnet-release.yml:70,80-83,115-116` expand `${{ inputs.version }}` and `${{ inputs.bump }}` directly into `run:` scripts.
  - The version check is the glob `[0-9]*.[0-9]*.[0-9]*`, which accepts any trailing characters. The value then goes into `perl -pi -e` and `sed -i "s|...|$version|"` replacements.
- **Impact:** needs workflow-dispatch rights (repository write access), but gives code execution in a job that holds `contents: write` and, in `release.yml`, the Apple signing secrets.
- **Exact fix:**
  - Add `env: REQUESTED_VERSION: ${{ inputs.version }}` and `BUMP: ${{ inputs.bump }}` to the step.
  - Use `requested="$REQUESTED_VERSION"` and `case "$BUMP"` in place of the `${{ }}` expansions.
  - Replace the `case` glob with `[[ "$version" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]] || { echo "invalid version"; exit 1; }`.
  - Do the same for `${{ steps.pick.outputs.version }}` and `${{ steps.pick.outputs.tag }}` in `dotnet-release.yml:115-116`.

### BUNYI-23: release actions pinned to mutable tags, Low, CWE-829. Not fixed (workflow file).

- **Description:** `actions/checkout@v7`, `actions/upload-artifact@v7`, `actions/download-artifact@v8`, `actions/setup-dotnet@v6` and `actions/setup-python@v6` are referenced by tag in `release.yml` and `dotnet-release.yml`. Those jobs hold signing secrets and `contents: write`. The third-party Certum action and the reusable security-review workflow are already SHA-pinned.
- **Exact fix:** replace each `@vN` with `@<full commit sha> # vN` in both release workflows, and let Dependabot's `github-actions` ecosystem keep them current.
